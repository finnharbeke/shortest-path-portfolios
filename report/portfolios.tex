\section{Portfolios}
\label{sec:portfolios}

We propose to solve \cref{prob:shortest-path} with the framework given in \cref{alg:portfolio}. Given $\mathcal O(k n^3)$ space, how can we compute portfolios of $k$ paths in polynomial time, such that for any graph weight realization and query $(s, t)$, the shortest path in the respective portfolio is close to the optimal shortest path from $s$ to $t$.
In this section we propose three different algorithms solving \cref{prob:portfolio}.

\subsection{Algorithms}
\label{sec:algorithms}

If you consider the maximization problem of the portfolio optimization problem, then the value function is a monotone submodular function, as pointed out by \cite{miltos} and initially shown by \cite{kr18}. Thus, the widespread \textit{Greedy} algorithm provides a $(1 - 1/e)$-factor approximation.
While there do not exist the same proven guarantees, we can use the same approach to greedily build a portfolio.
It builds the solution set iteratively, starting with the path that is the cheapest in expectation and then adding one path at a time to the set, such that at every step the cost is minimised over all candidates. We describe the procedure in \cref{alg:greedy}.
%As shown by \cref{nemhauser} it is thus a $(1 - 1/e)$ approximation.

\begin{algorithm}
\caption{Greedy Algorithm for \nameref{prob:portfolio}.}
\label{alg:greedy}
\begin{algorithmic}[1]
\Procedure{Greedy}{$G$, $\mathcal C$, $\mathcal D$, $s$, $t$}
\State $\mathcal K_{s,t} \gets \emptyset$
\State $\mathcal P_{s,t} \gets$ the set of all paths from $s$ to $t$
\For{$i \gets 1$ \dots $k$}
  \State $P^\dagger \gets$ none
  \State best $\gets \infty$ 
  \For{$P \in \mathcal P_{s,t}$}
    \If{$\text{cost}\left(\mathcal K_{s,t} \cup \{P\}\right) < \text{best}$}
      \State $P^\dagger \gets P$
    \EndIf
  \EndFor
  \State $\mathcal K_{s,t} =\mathcal K_{s,t} \cup \{P^\dagger\}$ 
\EndFor
\State \Return $\mathcal K^k_{s,t}$
\EndProcedure
\end{algorithmic}
\end{algorithm}

Greedy iterates over the entire set $\mathcal P_{s,t}$ in each round. Since $\mathcal P_{s,t}$ can contain exponentially many paths, its worst-case running time is exponential in $n$. Even for the modest $n = 67$ of \cref{shanghai}, enumerating all $s$-$t$ paths is computationally costly. Still, for any algorithm that builds $\mathcal K_{s,t}$ element by element, Greedy is the one that takes the best choice at every step.

An alternative approach is to rank paths by how often they are the shortest. For each path $P \in \mathcal P_{s,t}$, define its \emph{frequency} as
\[
\Pr(P^*_{s,t} = P) = \Pr_{c \sim \mathcal D}\left[P = \argmin_{P' \in \mathcal P_{s,t}} f_c(P')\right].
\]

The \emph{most frequent shortest paths} (MFSP) algorithm simply selects the $k$ paths with the highest frequency:

\begin{algorithm}
\caption{Most Frequent Shortest Paths (MFSP) for \nameref{prob:portfolio}.}
\label{alg:mfsp}
\begin{algorithmic}[1]
\Procedure{MFSP}{$G$, $\mathcal C$, $\mathcal D$, $k$, $s$, $t$}
  \State $\text{freq}[\cdot] \gets \text{empty dictionary}$
  \For{$c \in \mathcal C$}
    \State $P \gets \textsc{Dijkstra}(G,\, s,\, t,\, c)$ \Comment{Shortest under $c$.}
    \State $\text{freq}[P] \gets \text{freq}[P] + 1$
  \EndFor
  \State \Return $k$ paths with largest $\text{freq}[\cdot]$
\EndProcedure
\end{algorithmic}
\end{algorithm}

Unlike Greedy, MFSP never enumerates $\mathcal P_{s,t}$ explicitly. Its runtime is dominated by $N$ Dijkstra calls, each taking $\mathcal O(m \log n)$ time, yielding $T^0(\textsc{MFSP}) = \mathcal O(N m \log n)$ per pair $(s, t)$. The query phase is unchanged: given a realised $c$, evaluate the $k$ portfolio paths under $f_c$ and return the cheapest.

Both \cref{alg:greedy,alg:mfsp} rely on repeated shortest-path computations under the full distribution $\mathcal D$. A lighter alternative is to use only the \emph{expected} edge costs
\[
\overline c(e) = \mathbb{E}_{c \sim \mathcal D}[c(e)],
\]
and obtain $k$ candidate paths by repeatedly running Dijkstra while penalising edges that have already been selected. Concretely, after finding a path $P$, we multiply the expected cost of every edge in $P$ by a penalty factor $\lambda > 1$, so that subsequent shortest-path computations are discouraged from reusing the same edges and instead explore alternative routes. The procedure is given in \cref{alg:penalised}.

\begin{algorithm}
\caption{$\lambda$-Penalised Dijkstra for \nameref{prob:portfolio}.}
\label{alg:penalised}
\begin{algorithmic}[1]
\Procedure{$\lambda$-PenalisedDijkstra}{$G$, $\mathcal C$, $\mathcal D$, $k$, $s$, $t$}
  \State $\overline c \gets \mathbb{E}_{c \sim \mathcal D}[c(\cdot)]$
  \State $\mathcal K_{s,t} \gets \emptyset$
  \State $p[e] \gets 1$ for all $e \in E$ \Comment{Edge penalties}
  \For{$i \gets 1$ \dots $k$}
    \State $P \gets \textsc{Dijkstra}(G,\, s,\, t,\, \overline c \cdot p)$
    \State $\mathcal K_{s,t} \gets \mathcal K_{s,t} \cup \{P\}$
    \For{$e \in P$}
      \State $p[e] \gets \lambda \cdot p[e]$ \Comment{Penalise the used edges.}
    \EndFor
  \EndFor
  \State \Return $\mathcal K_{s,t}$
\EndProcedure
\end{algorithmic}
\end{algorithm}

Penalised Dijkstra never consults the full distribution $\mathcal D$ beyond computing the per-edge expectation $\overline c$. Its preprocessing cost is a single pass over $\mathcal C$ to compute means ($\mathcal O(N m)$) followed by $k$ Dijkstra calls on the mean-weight graph ($\mathcal O(k m \log n)$). Because it relies solely on expected costs, it ignores the stochastic nature of edge weights entirely: a path that is never the shortest under any realisation but has low expected cost may be selected, while a path that is frequently the shortest under many $c \in \mathcal C$ may be missed if its expected cost is high.

\subsection{Quantitative Analysis}

\begin{figure*}
    \centering
    \includegraphics{figures/sh_ratios.pdf}
\caption{The observed mean of the expected approximation factor of the algorithms presented in \cref{sec:algorithms}, when used as the \textsc{PortfolioAlg} for \cref{alg:portfolio}. The mean is observed over $r$ uniformly sampled $(s, t)$ pairs of the graph in \cref{shanghai}, the Shanghai Dataset, where $r=334$ for $\lambda$-penalised Dijkstra and $r=167$ for the other algorithms. The error bands are 95\% confidence intervals on the sampled expected approximation factors.}
\label{fig:sh_ratios}
\end{figure*}

In \cref{sec:algorithms} we described three different approaches to solve \cref{prob:portfolio}. With the framework given in \cref{alg:portfolio}, we thus have three full algorithms for \cref{prob:shortest-path}, all of them are parametrised by $k$ while $\lambda$-penalised Dijkstra has an additional parameter.
Taking \cref{shanghai}, we can evaluate their performance on that graph and its edge cost distribution. As discussed in \cref{sec:prelim}, for a query $(s,t)$ we are interested in the ratio between the expected cost of the algorithm's answer and the expected cost of the shortest path, denoted by $\alpha(\textsc{alg}, \cref{shanghai}; s, t)$. I.e.~how much more does the answer cost than optimally possible. Over $r$ uniformly sampled $(s,t)$ queries we then estimate the expected value of that ratio for any query with $\overline\alpha_r(\textsc{alg}, \cref{shanghai})$. In \cref{fig:sh_ratios}, those numbers are visualised.

At $k=1$ all algorithms achieve nearly the same expected approximation factor of roughly $1.018$. As $k$ grows, every algorithm improves monotonically as expected, but the rates at which they do differ sharply. Greedy and MFSP drop quickly: their extra cost over optimal is already below $0.5\%$ at $k=2$ and reaches mere hundredths of a percent by $k=8$. By contrast, the $\lambda$-penalised Dijkstra variants decay more slowly---the best-tuned case ($\lambda=1.2$) retains an excess of roughly $0.12\%$ at $k=8$, an order of magnitude worse than Greedy or MFSP. This must be because penalised Dijkstra, only using expected edge costs and reweighing edges, yields paths of a diversity that is different from the diversity that is valuable to portfolios. MFSP performs similarly to Greedy across all $k$, despite never enumerating the full path set and requiring only a fixed number of Dijkstra runs in preprocessing. This is a positive result, given MFSP is one of the simplest polynomial-time algorithms that can make use of information in the entire distribution.

The central tradeoff we are exploring with the \cref{alg:portfolio} approach to solving \nameref{prob:shortest-path} is the one between answer quality and query runtime. \cref{alg:dijkstra} is the one extreme, that does all the work at query time. It has a query runtime $T^q(\textsc{Alg})$ of $\mathcal O(m \log n)$ and grants perfect answer quality. The query runtime  of \cref{alg:portfolio} is $\mathcal O(kn)$, for evaluating the costs of each of the $k$ paths in $\mathcal K_{s,t}$. With a higher $k$ runtime increases linearly, but the expected approximation factor decreases, we can even hit perfect scores like Dijkstra. From a sample of different $(s,t)$ query pairs, we visualise the tradeoff in \cref{fig:tradeoff}. For the sake of visual clarity, we omit the results of $\lambda$-penalised Dijkstra.
We see that for all pairs, the query runtimes are less than that of Dijkstra for portfolios with $k = 3$ or less. Dijkstra's queries take about the time of evaluating portfolios with 4-6 paths. For bigger graphs, Dijkstra should only get slower in comparison if there are more than a linear amount of edges.

\subsection{Qualitative Analysis}
\label{sec:qualitative}

Let us take a look at an example query in \cref{shanghai} and how the different algorithms preprocesseed the graph to compute a suiting portfolio. A particular portfolio induces a partition on $\mathcal C$, we can group its cost functions by which ones assign the first path the cheapest cost, which ones assign the second path the cheapest cost and so on. Let us denote that partition for a given portfolio $\mathcal K$ by
\[
Q(\mathcal K) = \left\{\left\{ c\in\mathcal C\mid \forall P'\in\mathcal K\ c(P) \le c(P')\right\} \mid P \in \mathcal K\right\}.
\]

Every set in $Q(\mathcal K)$ is thus also an event of the probability space of the distribution $\mathcal D$. It is the event that ``$P$ is the cheapest of all paths in $\mathcal K$''. We denote its probability by
\[
\Pr[P\text{ wins }\mathcal K] = \Pr\left[\left\{ c\in\mathcal C\mid \forall P'\in\mathcal K\ c(P) \le c(P')\right\}\right].
\]

If $\Pr[P\text{ wins }\mathcal K]$ is evenly distributed across all $P\in\mathcal K$, then each path carries its weight and the portfolio covers the distribution broadly. But even a path that is unlikely to win overall can be valuable: when it does win, it may bring a significant decrease in cost compared to the other candidates, justifying its place in the portfolio.

For a single set in a partition $Q(\mathcal K)$, where some path $P$ is the one that wins, we can observe the typical ``traffic situation'' for that event. Let us define the relative mean cost of an edge $e\in E$ in that set, as a ratio with the overall mean cost of $e$:
\[
\frac{\overline c_{P,\mathcal K}(e)}{\overline c(e)} = \frac{\mathbb E_{c\sim D}[c(e) \mid P\text{ wins }\mathcal K]}{\mathbb E_{c\sim D}[c(e)]}
\]

For the pair $(17,49)$ in \cref{shanghai}, we see the paths chosen by Greedy and MFSP, as well as the respective $\Pr[P\text{ wins }\mathcal K]$ and the $\frac{\overline c_{P,\mathcal K}(e)}{\overline c(e)}$ for all edges on the paths visualised in \cref{fig:1749g_vs_m}. The figure contains a lot of information, but we think it is all necessary information to be able to get some insight on the given portfolios and their differences. 
The chosen pair is a very difficult query, in the sense that the expected approximation factors above $1.01$ are clearly outside of the $95\%$ confidence intervals for $k=3$ in \cref{fig:sh_ratios}. This must be due to many different paths with similar distances between the source and target. We see that the two vertices are sort of on two ends of a manhattan-like grid.
The edge that Greedy has over MFSP is well emphasised by the respective choices of the third path in the portfolio. Greedy is able to find the path that shines only rather rare scenarios, but when it does it shines brightly and can bring the biggest decrease in expected cost of the portfolio. Such a path will not be found by MFSP until a larger $k$ is being used.
For this query $\lambda$-penalised Dijkstra actually finds the same path as the third part of its portfolio, but chooses a second path that is less similar to the red path than the blue one and thus still has a worse expected approximation factor than MFSP's portfolio. \cref{fig:1749g_vs_pd}
